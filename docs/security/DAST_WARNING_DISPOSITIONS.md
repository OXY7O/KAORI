# KAORI DAST Warning Dispositions

This document records reviewed dispositions for the warning families observed by the KAORI ZAP baseline. It is evidence for operator/security review; it does **not** replace the runtime DAST gate. The baseline remains authoritative for new failures, and `FAIL-NEW` must remain zero.

Current evidence source: KAORI staging Runtime & DAST, ZAP 2.17.0.

The parser proves it remains only the hidden input value and creates no SVG or event attributes. Do not weaken or remove this proof. |

## Centralized response-security contract

Browser response-security ownership remains in `app/bootstrap/security.py`. Page-local templates must not introduce their own competing CSP or site-isolation headers.

The HTML baseline is:

- nonce-protected `script-src 'self'`;
- temporary Alpine compatibility allowance `'unsafe-eval'`;
- no script `'unsafe-inline'`;
- `script-src-attr 'none'`;
- `frame-ancestors 'none'`;
- `object-src 'none'`;
- `Cross-Origin-Opener-Policy: same-origin`;
- `Cross-Origin-Embedder-Policy: require-corp`;
- `Cross-Origin-Resource-Policy: same-origin` on all responses.

Static/resource responses receive CORP plus MIME-sniffing protection, but do not receive document-level COEP/COOP headers.

## Scanner authority

Do not add broad ZAP ignore rules for these families. `.github/ci/run-zap-baseline.sh` remains the runtime scanner authority and the staging/release gate must continue to reject any genuine new failure. Reviewed warning dispositions are documentation and regression evidence, not permission to make `FAIL-NEW` non-zero.

## Sanitized GitHub Actions evidence (candidate #4400)

The existing `Full Admission → Runtime & DAST` gate executes ZAP once, generating traditional `baseline.json` and `baseline.html`. The new bounded evidence formatter (`scripts/ci_zap_safe_summary.py`) **reads** the JSON generated by that exact run; it is **not** a new ZAP scan, SARIF converter, or change to `-I` warning behavior. Only source SHA and numerical counts of grouped alert records per ZAP `riskcode` (High, Medium, Low, Informational) may appear in the Actions job summary and **sanitized-summary-only** artifact. No URLs, cookies, headers, bodies, attack payloads, message/title text or other HTTP metadata are copied.

The JSON aggregate records grouped alert entries, **not** native CLI `FAIL-NEW`/`WARN-NEW`/`PASS` status. Full Admission's existing ZAP process and its step exit status remain authoritative. Source SHA comes from the Full Admission validation-profile result, not a guessed merge SHA. A failed/missing/incompatible JSON schema is reported as **NOT VERIFIED**, never silently presented as zero findings. A staging Fast Smoke reuse is **not** a fresh ZAP run and therefore must not publish a new DAST summary.

The summary is stored on the **actual Full Admission run** with its exact source SHA; it is **not** uploaded to GitHub Security → Code scanning. Endpoint-only ZAP findings do not automatically map to repository source-file lines, and raw SARIF would expose HTTP evidence. Privacy/source-location criteria remain governed by canonical #4391 and [third-party reporting policy](THIRD_PARTY_CODE_SCANNING_REPORTING.md). This reporting change requires Developer Check, all Full Admission gates, staging UAT, independent review and human Security acceptance; a green CI job alone does not authorize `main` promotion.
