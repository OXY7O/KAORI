How LDAP provisioning works

Use this workflow for controlled, administrator-approved directory access.

Details Collapse
1

Prepare the provider

Configure the server, Base DN, bind identity, secret environment reference, search filter, and TLS mode.

2

Find one identity

Select the intended directory and search using identity metadata. KAORI reads matching directory entries only.

3

Assign KAORI access

Choose the application role and decide whether the projected account becomes active immediately.

4

Provision and authenticate

KAORI stores the identity link and authorization state. The user continues signing in with LDAP-managed credentials.

Authentication boundary

LDAP remains the authoritative credential source after the user is provisioned into KAORI.

Details Collapse

Provisioning does not copy or reset an LDAP password. KAORI keeps identity metadata, the external subject link, role assignment, and lifecycle state; the LDAP directory remains the credential authority.

Before searching

Confirm the directory integration is operational.

Details Collapse

The LDAP provider is enabled and its configuration has been validated.

The bind password environment variable is available to the KAORI runtime.

The intended KAORI role already exists and is active.

The directory identity does not conflict with an existing KAORI username or email address.
