Baseline · Full Validation

AppRole login is the authentication step. A self-lookup read is the required authenticated token check.

# Attach to the approved KAORI AppRole.
# Vault health and auth/approle/login require no token ACL grant.
path "auth/token/lookup-self" {
  capabilities = ["read"]
}

Optional · Mount Discovery

Only if approved for `GET /v1/sys/mounts`. A denied optional check is Limited, not a required validation failure.

# Separate optional policy: mount names may reveal topology.
path "sys/mounts" {
  capabilities = ["read"]
}

Optional · Approved KV v2 Metadata

Replace the mount placeholder with a narrowly approved KV v2 mount; this is separate inventory authorization, not Full Validation.

# Replace approved-kv-mount with a reviewed KV v2 mount name.
# List names at the root, read/list metadata at approved paths.
path "approved-kv-mount/metadata" {
  capabilities = ["list"]
}
path "approved-kv-mount/metadata/*" {
  capabilities = ["read", "list"]
}

Provider Authority & Sensitive Data Boundary

A Vault administrator reviews and assigns these independent policies. Never add KV `data/*`, token management, SecretID, ACL writes, or PKI issuance permissions to the baseline. Metadata paths and key names may themselves be sensitive.
