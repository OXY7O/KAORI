Minimum Validation RBAC Examples

Keep baseline discovery separate from optional access to sensitive Kubernetes resources.

Validation Baseline · ClusterRole And ClusterRoleBinding

Read-only discovery and inventory metadata without Kubernetes Secret access.

 
apiVersion: v1
kind: ServiceAccount
metadata:
  name: kaori
  namespace: kaori-system
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: kaori-validation-reader
rules:
  - nonResourceURLs: ["/api", "/apis", "/version", "/healthz", "/readyz"]
    verbs: ["get"]
  - apiGroups: ["authorization.k8s.io"]
    resources: ["selfsubjectaccessreviews"]
    verbs: ["create"]
  - apiGroups: [""]
    resources: ["nodes", "namespaces", "pods", "services", "endpoints", "persistentvolumes", "persistentvolumeclaims", "resourcequotas", "configmaps"]
    verbs: ["get", "list"]
  - apiGroups: ["apps"]
    resources: ["deployments", "statefulsets", "daemonsets", "replicasets"]
    verbs: ["get", "list"]
  - apiGroups: ["batch"]
    resources: ["jobs", "cronjobs"]
    verbs: ["get", "list"]
  - apiGroups: ["networking.k8s.io"]
    resources: ["ingresses", "networkpolicies"]
    verbs: ["get", "list"]
  - apiGroups: ["storage.k8s.io"]
    resources: ["storageclasses", "csinodes", "csidrivers"]
    verbs: ["get", "list"]
  - apiGroups: ["policy"]
    resources: ["poddisruptionbudgets"]
    verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: kaori-validation-reader
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: kaori-validation-reader
subjects:
  - kind: ServiceAccount
    name: kaori
    namespace: kaori-system

Baseline Boundary

This baseline intentionally excludes Secrets and write verbs. It supports discovery, normalized inventory, compatibility validation, and effective read-access checks.

Optional Governance Secret Reader · Namespace Scope

Add only for namespaces included in TLS Governance or approved Secret metadata workflows.

 
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: kaori-governance-secret-reader
  namespace: <approved-namespace>
rules:
  - apiGroups: [""]
    resources: ["secrets"]
    verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: kaori-governance-secret-reader
  namespace: <approved-namespace>
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: Role
  name: kaori-governance-secret-reader
subjects:
  - kind: ServiceAccount
    name: kaori
    namespace: kaori-system

Sensitive Permission

Kubernetes get/list permission on Secrets can expose Secret data returned by the API. Grant this Role only in explicitly approved namespaces and keep KAORI allow-list, protected-secret, reveal, and Activity Audit guardrails enabled.
