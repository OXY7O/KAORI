Minimum Validation RBAC Example

Use this read-only baseline for the KAORI service account, then remove resources for capabilities you intentionally disable.

ClusterRole And ClusterRoleBinding

Read access for discovery, inventory evidence, and Self Subject Access Review validation.

 
apiVersion: v1
kind: ServiceAccount
metadata:
  name: kaori
  namespace: kaori-system
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRole
metadata:
  name: kaori-validation-reader
rules:
  - nonResourceURLs: ["/api", "/apis", "/version", "/healthz", "/readyz"]
    verbs: ["get"]
  - apiGroups: ["authorization.k8s.io"]
    resources: ["selfsubjectaccessreviews"]
    verbs: ["create"]
  - apiGroups: [""]
    resources:
      - nodes
      - namespaces
      - pods
      - services
      - endpoints
      - persistentvolumes
      - persistentvolumeclaims
      - resourcequotas
      - configmaps
      - secrets
    verbs: ["get", "list"]
  - apiGroups: ["apps"]
    resources: ["deployments", "statefulsets", "daemonsets", "replicasets"]
    verbs: ["get", "list"]
  - apiGroups: ["batch"]
    resources: ["jobs", "cronjobs"]
    verbs: ["get", "list"]
  - apiGroups: ["networking.k8s.io"]
    resources: ["ingresses", "networkpolicies"]
    verbs: ["get", "list"]
  - apiGroups: ["storage.k8s.io"]
    resources: ["storageclasses", "csinodes", "csidrivers"]
    verbs: ["get", "list"]
  - apiGroups: ["policy"]
    resources: ["poddisruptionbudgets"]
    verbs: ["get", "list"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: kaori-validation-reader
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: kaori-validation-reader
subjects:
  - kind: ServiceAccount
    name: kaori
    namespace: kaori-system

Security Boundary

This role is read-only. Secret values, ConfigMap changes, remediation actions, and other write operations require separate namespace-scoped roles and KAORI approval controls.
