Operational Boundary

Kubernetes remains authoritative for live resources. KAORI separates read-only discovery from explicit operational changes.

KAORI Reads

  • Cluster metadata and API resources
  • Inventory objects and relationships
  • Runtime and compatibility evidence

KAORI Does Not Modify

  • Workloads during inventory sync
  • Services or networking resources
  • ConfigMaps or Secrets outside dedicated workflows

Configuration changes run only through dedicated Kubernetes Operations workflows with permission checks, validation, and Activity Audit Log evidence.
